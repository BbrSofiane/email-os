## Goal

Make the shell a thin adapter. Commands translate IPC to core calls, the state is a small struct, and anything that is mail logic lives in `mail-core`.

1. **Collapse `Backend`.** Hold one `GmailCore` in `AppState` and delete the forwarding `impl`. If something still has to know the session kind, ask the core (the session policy) instead of matching on a shell enum.
2. **Move domain logic into `mail-core`** where it belongs. Candidates: reply-draft revalidation (`validate_reply_conversation`, `require_draft_account`, `active_account`), and anything else in the shell that decides mail behaviour rather than adapting IPC. Each move keeps its tests and gets core-level tests where it had only shell tests.
3. **Split what remains** of `lib.rs` into modules along real seams. Suggested layout (you decide from reading it): `state.rs`; `commands/` grouped by surface (mailbox, drafts, attachments, account, lifecycle and close, transition); `setup.rs`, holding `run()`, mode selection and opening the core. `lib.rs` keeps only the module declarations, the `run` entry point and the `generate_handler!` list. Move each test module next to the code it tests.
