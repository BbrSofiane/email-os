Step 2 LAYOUT (P2). Reader geometry is off the product grid. `.reader-pane` uses `padding: .5rem .75rem` (style.css ~1319-1323), so the subject starts near 12px while the header title and the inbox list sit on the 50px inset; opening a row visibly shifts the text edge. The undocked compose card uses the 50px margin (~2284) but the docked one uses 0 (~2300). Put the reader on the 50px inset (decide the right edge deliberately and keep long-line measure at 65ch), make docked/undocked compose margins agree, and fix the loading skeleton row height (style.css ~1418-1421 uses 1.4em while its comment says the collapsed height is 2em, so the pane may still jump). Keep J/K reader navigation smooth with no empty frame. Reconcile DESIGN.md gap 16 and the reader geometry docs.

Step 3 CLARIFY (P2). (a) The reply heading is always `Reply draft to {From name}` (ReplyComposer.vue ~111), but To defaults from Reply-To (generated.ts ~426; draft_core.rs ~376), so on list/newsletter/support-desk mail the heading and the To row disagree and Cc/Subject auto-open (DraftEditorCore ~135, ~159). Derive the heading from the actual To (or add a terse 'Reply-To differs' line) and verify the compact form still holds when Reply-To differs. (b) The Message DTO has no Cc: the reader shows `to X, Y` (ReaderView ~1017) and Details lists From/To/Sent only (~1050-1082), so a Cc'd thread looks complete and a reply silently drops people. Say so plainly and tersely, e.g. 'Cc not cached' where Cc is unknown; do not fabricate Cc and do not change the wire format unless trivial and safe. (c) Replace the internal 'Prepare reply' wording with plain 'Reply' in titles, labels, palette and tests, keeping the R hint. (d) `describeError` leaks `invalid field:` (ReaderView ~204): replace with a plain message. (e) AttachmentChooser empty state is a ~230-char line (AttachmentChooser.vue ~86) and uses 'Known files' jargon: shorten to terse factual copy. Voice: terse, factual, sentence-case, no exclamation marks.

Step 4 POLISH: affordances and accessibility (P2). (a) The composer field underline (Seam #474543) is 1.36:1 on the raised surface and is the only at-rest cue that an empty field is an input; raise it to >=3:1 or add a second at-rest cue, staying within DESIGN.md tokens (add a token only if needed and document it). (b) `.composer-caveat-toggle` is ~18x18px; enlarge the hit area (not necessarily the glyph). (c) `.participant` spans in the reader (ReaderView ~1054, ~1071) are role-less `tabindex=0` with a colour-only/dotted-underline focus style and add a tab stop per recipient: either give them a real visible focus ring and a role, or remove the extra tab stops (the full address must stay reachable by keyboard and screen reader). (d) AttachmentChooser buttons all read 'Save to Downloads' (~83): give each a per-file accessible label like the inline ones. Align inline 'Save' vs chooser 'Save to Downloads' wording. (e) MessageAttachments 'Could not load file details.' (~62) has no retry: add a Retry action. Do not use Graphite (#8e8a87) for meaningful glyphs on focus-fill (2.75:1). Keep every existing live region quiet (status line announces only meaningful transitions).

(b) Any interleaved `>` line in the prose forces the whole body to monospace at 13.6px (message-body-format.ts ~12-17, documented limitation): fix if small and safe (e.g. only force mono when the non-quoted prose itself looks tabular/aligned), otherwise keep the limitation and document it.
