## Main bug (steps 5, 6, 7): parent-attached listeners never run inside the mail frame on WebKit

`src/components/HtmlMessageFrame.vue` renders mail in a `srcdoc` iframe with `sandbox="allow-same-origin"` (no `allow-scripts`), then the parent attaches listeners to the frame's document (around lines 148-152): `doc.addEventListener('click', …, true)`, `doc.addEventListener('keydown', …, true)` and `img.addEventListener('load', fit)`.

WebKit refuses to run any event listener whose target document is in a sandboxed frame without `allow-scripts`, even when the listener function belongs to the parent realm. Chromium (and so the Android WebView) runs them. That's why Android passed and macOS fails. Evidence from the Web Inspector console on macOS:
- A test listener added from the parent with `frame.contentDocument.addEventListener('click', …, true)` ran 0 times after a dispatched click. The same listener on the parent `document` ran once.
- Each blocked call logs "Blocked script execution in 'about:srcdoc' because the document's frame is sandboxed and the 'allow-scripts' permission is not set."
- Parent-side DOM APIs on the frame still work (`contentDocument.querySelector`, setting `img.src`, reading layout). Only listeners are blocked.

User-visible effects on macOS:
- Step 5: clicking an https link or a `mailto:` link in conv-20 does nothing. There's no confirmation dialog and no New message.
- Step 6: after clicking inside a message, the frame has focus and `j`/`k` do nothing, because the keydown forwarder never runs. With focus outside the frame, `j`/`k` work.
- Image `load` → `fit` never fires, so height fitting relies only on the ResizeObserver path.
- Step 7: `FRAME_PROBE_SOURCE` in `tests/rendered/html-frame-probe.ts` gives 36 PASS and 1 FAIL. The FAIL is "remote image blocked by CSP — [], width=0". Its `securitypolicyviolation` listener is attached to the frame document from the parent, so it never runs on WebKit. WebKit's own console report shows the CSP did block the image ("Refused to load https://probe-image.invalid/p.png because it does not appear in the img-src directive"). Every no-script check passed.

Constraints:
- Do NOT add `allow-scripts` or any other sandbox token. ADR 0006 decision 9 forbids it, and the no-script guarantee and fail-closed Tauri-global guard must keep holding.
- Keep text selection and copy inside the message working, along with keyboard link activation (Enter/Space on a link) and the per-link confirmation flow.
- Behaviour on Chromium/Android must not regress.

Design the fix (record it in the ADR's implementation record if it changes the approach), implement it with focused tests, and make the probe's CSP check work on WebKit without weakening it, e.g. a signal that doesn't depend on a listener inside the frame.

The stored CRC is `ef bf 6b db` and the correct one is `ef a2 a7 5b`. The `ef bf` looks like a UTF-8 replacement-character mangling, so check how the file was produced.
