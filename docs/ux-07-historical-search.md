# UX-07 — Historical search and return

Implemented journey: `/` (or Search) → submit → result → reader → Back to the same query, loaded results, focused reference and list anchor → Back to the previous browsing context. Search does not mark messages read. Existing explicit setters, selection, Undo, Activity and local-only drafts remain in use.

## Query contract

`search_mail(SearchRequest) → SearchPage` and `cancel_search_mail()` are narrow, read-only commands. Requests carry the active account, query, continuation and an explicit cached-only choice. Rust owns validation and evaluation; the browser fake mirrors it for synthetic preview only.

- Up to 512 UTF-8 bytes. Adjacent terms / uppercase `AND` intersect; uppercase `OR` separates alternatives. AND has higher precedence. Prefix `-` excludes a term or field phrase.
- Straight double quotes group a literal phrase. Matching is case-insensitive Unicode-lowercased substring matching, not stemming, regex, fuzzy matching or Gmail's query language.
- Unqualified text searches subject, known From/To names and addresses, and cached plain-text message bodies. `from:`, `to:` and `subject:` restrict those fields. A conversation matches over its known message stack (criteria may match different messages).
- Unknown operators, parentheses/braces, escapes, unmatched quotes, missing values and dangling operators reject with `invalid_request/searchQuery`. Colons inside a quoted phrase are literal text. No Cc/Bcc, labels, date/time operators or implicit timezone conversion. Message timestamps remain UTC facts; existing localized list date grouping is unchanged.
- Cached mode inspects at most the 1,000 newest known conversation candidates, including retained recovery context, and only their known plain-text content. It always reports incomplete coverage. Missing headers/bodies and HTML-only content are not fabricated.

## Provider reads and coverage

The provider enumerates **20 mailbox candidates per page**, without an INBOX filter and with Spam/Trash excluded (`includeSpamTrash=false`). It reads each candidate through the existing paced/authenticated/cancellable thread reader and sync's 16 MiB aggregate retained-data budget and evaluates the same AST as cached mode. This deliberate first implementation avoids silently substituting Gmail's tokenization/stemming for our substring semantics. It reaches older archived mail beyond inbox discovery, but is a **progressive scan**, not indexed Gmail search: a selective query may need multiple empty candidate pages before finding a match. The UI explicitly says this and keeps continuation available on empty pages. Totals are unknown. Provider-side query acceleration is deferred until it can provably preserve the supported semantics.

Provider failures (including auth expiry, rate limits, missing/invalid responses) stay errors, not empty results. The user can retry or explicitly choose cached-only search. A known disconnected/offline account uses the local cache with an incompleteness disclosure. A failure while continuing preserves loaded rows and the exact retry cursor. Missing provider threads are omitted; opening an evicted result performs a visible exact-ID read, and a missing body/result produces the existing reader error, never a substitute conversation.

Cursors are bound to account and exact query. The frontend fences list/detail/account/navigation generations, deduplicates account-scoped identities, and cancels provider search on replacement/context exit/unmount. Lifecycle cancellation and SQLite generation checks also fence native writes. Search pages, explicit missing-result loads and action rehydration additionally capture the store connection's observation revision before provider reads. Admission rejects with `busy` if any intervening store write occurred, including history/deletion checkpoints or confirmed setters; an explicit retry takes a fresh observation. This deliberately conservative fence can reject an otherwise usable page after an unrelated write, rather than overwrite newer mailbox facts. Contact-history queries are explicitly cached-only, so J/K never initiates or cancels provider traversal.

## Cache and operation safety

Search-only conversations have a separate 100-conversation retention budget tracked in `gmail_search_cache`. Admission does not advance/reset inbox discovery or history checkpoints, and search-only rows do not appear as inbox discoveries. A normally observed inbox row is promoted out of search-only membership. Inbox discovery's cap excludes search-only rows. Cached search coverage remains incomplete; it cannot reliably infer Spam/Trash membership where those facts were never cached.

Search admission is account/generation checked and transactional. Search eviction removes bodies and unpinned facts, never durable operations, immutable operation targets, preimages or recovery snapshots. Before accepting a single or group setter, genuinely missing exact conversation references are revalidated through bounded provider reads after the normal account/capability checks. Retained message facts plus an account-scoped recovery snapshot already provide sufficient local action context; these actions do not require provider reads. Deferred action paths carry the original admission generation through provider registration, offline fallback and transactional acceptance, so reconnecting the same account cannot revive an unaccepted command from the previous lifecycle. Rehydrated rows and immutable targets/recovery snapshots are admitted in the same transaction; search eviction runs only after all group members have been considered. Durable idempotent replays do not require provider reads. A committed setter captures its existing durable recovery snapshot before any subsequent search eviction. Disconnect clears search membership with the rest of account data.

## Contact affordances

Activating the known contact name starts a From search; Copy name / Copy email remain independent explicit clipboard actions. Up to four actual cached matches are shown as recent-email links, from a bounded result page. These are local known history, not invented enrichment or a claim to provider-complete recency.

## Verification

Synthetic tests cover the full archived-result/reader/Back/previous-context journey, query grammar, editable shortcut safety, explicit invalid-query errors, stale responses, duplicate pages, continuation rate limits, contact/copy separation, named transport envelopes, native older-archive admission, account/generation fencing, provider pagination/defaults, and bounded eviction preserving operation recovery. P1 regressions additionally cover search observations racing confirmed archive/read and history deletions, single/mixed-group actions after six pages evict earlier results, known expired auth versus explicit cached search, and explicit query intent surviving background refresh during deferred cancellation while still respecting newer navigation/account/disposal intents. Mounted-App regressions exercise actual reader-open, Close/Back, same-context Inbox shortcut, recent-link, J/K and utility-destination boundaries; native regressions cover disconnect/reconnect before and during rehydration, final transactional generation checks, and local recovery actions during provider network/rate-limit failures.

No real mail access is needed or authorized by these tests. WKWebView keyboard/scroll calibration, live offline/auth/rate-limit behavior and disposable-account provider convergence remain manual/native verification gates; jsdom is not certification of those behaviors.
